# IndusAI Demo Guide

## Reset and entry

1. Open `http://localhost:3000`.
2. Choose **Applicant** from the demo entry cards, or use **Reset demo** in the header to restore the seeded Maharashtra scenario.
3. Use **Sahyadri Precision Components** as the primary fictional project.

## Presentation journey

1. Applicant: open **My Projects**, review the intake card, then **Generate project profile**. Open **Approval Roadmap**, select a node, and use the contextual assistant action.
2. Applicant: open **Documents**, process a prepared sample, inspect simulated OCR metadata, then return to the dashboard and resolve readiness issues. Use **Run readiness check**.
3. Applicant: open **Applications**, select an application, review its timeline, and use **Submit mock application** to create a shared reference and notification.
4. Officer: switch the labelled demo role switcher to **Government Officer**, open **Application Queue**, select the new application, and choose **Request correction + query**. This updates the application timeline and creates an applicant notification.
5. Applicant: switch back, open **Notifications**, follow the query to **Applications**, open the record, and choose **Submit corrected response**.
6. Officer: open **Inspections**, propose availability or confirm a mock slot. Open **Grievances** to inspect a timeline and add an officer response.
7. Applicant: create a grievance, open its detail, and use the illustrative escalation action when eligible. Explore **Incentives** and **Compliance & Renewals**.
8. Administrator: switch to **Administrator**, open **Regulatory Knowledge Base** or **Policy Update Review**, run **Run monitoring check**, then approve or reject the pending illustrative update. Open **Audit Logs** to see the generated activity.
9. Administrator or officer: open **System Analytics** / **SLA Monitoring** to review the illustrative charts.

## What the demo proves

The three roles consume one persisted state. Applicant submissions appear in the officer queue. Officer correction requests appear as applicant notifications and application timeline events. Applicant responses remain visible to officers. Regulatory monitoring creates a pending human-review item and an audit entry. All integrations, AI, OCR, DigiLocker, approvals, and analytics are illustrative frontend simulations.
